### Fixed

- `wizard/sms_composer.py`: sending to more than one record at a time never
  worked. Only the single-document composer computes `recipient_single_number`,
  and the override read it in every mode, so a server action, a list-view send
  or any multi-record selection sent each message to an empty recipient --
  Twilio saw the literal `False`, took it for a five-character short code and
  refused all of them. Setting such an action to *SMS (with note)* does not
  avoid it: core's `_run_action_sms_multi` passes `res_ids` and never `res_id`,
  so `comment_single_recipient` stays off and comment mode is a batch too.
  Batch sends now resolve each record's own number through
  `_sms_get_recipients_info` and render the template per record, so each
  contact reads their own details. Records with no usable number stop the batch
  before anything is sent and are named in the error; blacklisted numbers are
  passed over, as core does. A number edited in the single-recipient composer
  is now the one that gets the message, instead of the stored one.

- `models/message.py`: a refused send reported `Unexpected error! Contact admin
  or maintainer!` and left the provider's actual reason in the container log.
  `client_send` now raises with what the provider said, so the person sending
  reads the reason.

### Changed

- `doc/user_guide.md`, section *Messages*: describes sending to many records at
  once, that a batch is all-or-nothing, and that blacklisted contacts are
  skipped. Section *When something does not work* gains an entry for a send
  refused before it reached the provider.
