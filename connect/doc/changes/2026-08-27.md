### Changed

- `models/channel.py`: `Channel.transfer()` printed the Twilio response to the
  container's stdout on every transfer. It now logs at DEBUG instead, so the
  line is off by default and, when switched on, carries a timestamp and the
  module it came from.

### Fixed

- `models/call.py`: `Call.transfer()` and `Call.transfer_button()` are marked as
  unfinished and unreachable. Nothing calls either -- no Python caller, no view
  button, no JS -- and the transfer the phone panel performs is
  `connect.transfer_wizard.execute_transfer()`. The reasons the code below could
  not work as written are now recorded next to it: the call-state guard is
  switched off, the `user` argument is overwritten by whoever sits on the first
  channel, and the destination is hard-coded to a test SIP URI while the line
  that would join the two legs is commented out. No behaviour changed; nobody
  could reach any of it.
