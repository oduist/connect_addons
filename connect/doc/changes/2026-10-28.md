### Added

- `doc/admin_guide.md`, section *API keys*: the **Self-hosted Whisper** group
  — API URL, API key and TEST CONNECTION — for a speech-to-text server you run
  yourself, with the warning that its plain-HTTP connection belongs on a
  private network.

- `doc/admin_guide.md`, section *Transcription*: the new **Self-hosted
  Whisper** provider with its **Model** and **Language** settings, a table of
  which engine handles call recordings, voicemail and voice messages, and
  summaries for each provider, and the limits — 25 MB per recording (Twilio
  recordings are now fetched as MP3, which fits calls of 50 minutes and more),
  no speaker labels from Whisper, and the wait after a Whisper server restart.

- `doc/tech_spec.md`, new section *Speech-to-text*: the provider settings and
  how a provider is resolved, the dispatcher methods on `connect.settings`
  (`get_whisper_client`, `get_stt_error`, `transcribe_audio`,
  `action_test_whisper`), how each kind of audio is downloaded, and the gates,
  output formats and failure handling for recordings, voicemail and voice
  messages. The *Scope and status* section now lists speech-to-text as
  covered.

  ```diff
    ## Error handling
  + ## Speech-to-text
  + ### Settings fields (`connect.settings`)
  + ### Provider resolution
  + ### Methods on `connect.settings`
  + ### Audio download
  + ### Call recordings
  + ### Voicemail
  + ### Voice messages
  + ### Settings form
  ```

### Changed

- `doc/admin_guide.md`, section *API keys*: the OpenAI key is needed for call
  summaries with every transcription provider, not only when OpenAI
  transcribes.

- `doc/admin_guide.md`, section *Transcription*: rewritten around the three
  groups the tab now has — *Speech-to-text*, *Call Summary* and *Transcribe
  Rules*. The provider is always shown, because it now also decides who
  transcribes voicemail and voice messages; the summary settings say that the
  summary always comes from OpenAI and that a user's own prompt overrides the
  global one.

### Fixed

- `doc/admin_guide.md`, section *Transcription*: **Transcribe voice messages**
  was described as applying to voicemail. It controls incoming WhatsApp and
  MMS voice messages; voicemail is transcribed whenever its provider is
  configured, with no switch of its own.
