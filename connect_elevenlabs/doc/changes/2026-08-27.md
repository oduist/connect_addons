### Added

- `user_guide.md`: a **Booking appointments** section. The module has been able
  to book, list and cancel calendar meetings during a call since the calendar
  tools were added, but neither guide said so — the capability was reachable and
  undocumented. Covers what a caller can ask for, that the result is an ordinary
  calendar event with the call linked to it, how free time is worked out (gaps
  between existing events, one person, one day, defaulting to tomorrow), the
  fixed 08:00--18:00 window that ignores working schedules and time off, and the
  fact that an agent cancellation deletes the event rather than marking it
  cancelled.
- `admin_guide.md`: **The calendar tools that ship with the module** — the five
  webhook tools (`calendar_get_available_slots`, `calendar_create_event`,
  `calendar_get_current_date`, `calendar_get_meetings`,
  `calendar_remove_meeting`), the endpoints behind them, and the
  *Appointment Assistant* agent template that drives them. This is also why the
  module depends on `calendar`.
- `admin_guide.md`: three things to settle before pointing a number at the
  Appointment Assistant — that its shipped prompt **hard-codes `user_id=2`**, so
  until it is edited every appointment lands in the administrator's calendar;
  that the endpoints are `auth="public"` and gated only by the
  `elevenlabs_agent_token` setting sent as an `x-elevenlabs-agent-token` header,
  refusing when it does not match or is empty -- as a jsonrpc error envelope
  inside a `200`, not as an HTTP `401`; and that SYNC TOOLS is still required
  after an edit.
- `admin_guide.md`: the limits behind availability — hard-coded working hours
  rather than `resource.calendar`, only `calendar.event` counting as busy, one
  user and one day per query, `get_meetings` matching on attendee, and
  `remove_meeting` unlinking any event id it is given rather than only the
  caller's own.

### Changed

- `controllers/calendar.py` and `models/recording.py` printed to the container's
  stdout on every availability query and every transcription. Both now log at
  DEBUG, so the output is off by default and attributed to its module when
  switched on. The transcription line printed the whole ElevenLabs response
  object one line after the transcript had already been logged.
- `models/agent.py`: the **Print** button on the agent form
  (`print_config`) wrote the agent configuration to stdout. It now logs at INFO,
  so its output reaches the Odoo log where the rest of the module's output
  already goes -- the button is pressed deliberately, so it does not wait for
  DEBUG to be enabled.

### Fixed

- `get_available_slots` answered with the wrong date for every timezone east of
  UTC. The requested day became local midnight, was converted to UTC — 21:00 the
  evening before, for UTC+3 — and the 08:00--18:00 window was then built from
  that shifted date, so asking for 3 September from Europe/Chisinau returned
  slots labelled 2 September. The window is now wall-clock time on the requested
  day in the caller's timezone.
- Two further timezone faults on the same path: `calendar.event` values are
  naive UTC but were converted with `.astimezone()` directly, which reads a naive
  datetime as the *server's* local time and is correct only while the server runs
  on UTC; and the default day, used when the caller names none, came from the
  server's date rather than the caller's.
- Free intervals are clamped to the working window. A meeting running past 18:00
  used to produce a reversed interval (start 20:00, stop 18:00) and one ending
  before 08:00 pushed the first slot outside the window. Every slot is also
  returned as a formatted string now; the first was a string and the rest were
  datetimes.
