### Added

- `user_guide.md`: a **Booking appointments** section. The module has been able
  to book, list and cancel calendar meetings during a call since the calendar
  tools were added, but neither guide said so — the capability was reachable and
  undocumented. Covers what a caller can ask for, that the result is an ordinary
  calendar event with the call linked to it, how free time is worked out (gaps
  between existing events, one person, one day, defaulting to tomorrow), the
  fixed 08:00--18:00 window that ignores working schedules and time off, and the
  fact that an agent cancellation deletes the event rather than marking it
  cancelled.
- `admin_guide.md`: **The calendar tools that ship with the module** — the five
  webhook tools (`calendar_get_available_slots`, `calendar_create_event`,
  `calendar_get_current_date`, `calendar_get_meetings`,
  `calendar_remove_meeting`), the endpoints behind them, and the
  *Appointment Assistant* agent template that drives them. This is also why the
  module depends on `calendar`.
- `admin_guide.md`: three things to settle before pointing a number at the
  Appointment Assistant — that its shipped prompt **hard-codes `user_id=2`**, so
  until it is edited every appointment lands in the administrator's calendar;
  that the endpoints are `auth="public"` and gated only by the
  `elevenlabs_agent_token` setting sent as an `x-elevenlabs-agent-token` header,
  refusing with `401` when it does not match or is empty; and that SYNC TOOLS is
  still required after an edit.
- `admin_guide.md`: the limits behind availability — hard-coded working hours
  rather than `resource.calendar`, only `calendar.event` counting as busy, one
  user and one day per query, `get_meetings` matching on attendee, and
  `remove_meeting` unlinking any event id it is given rather than only the
  caller's own.
